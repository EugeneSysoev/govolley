# GoVolley: текущее состояние и целевой MVP

Дата: 19 октября 2026 года.

Статус: согласовано владельцем проекта 19 октября 2026 года. Документ описывает текущее состояние по исходникам и целевой MVP; реализация MVP этим согласованием не подтверждается.

Спецификация опубликована в [GitHub Issues: GoVolley MVP](https://github.com/EugeneSysoev/govolley/issues/1) с меткой `ready-for-agent`.

## Назначение и согласованные границы

GoVolley создаётся для одной школы пляжного волейбола на Пхукете. Основная аудитория — русскоязычные жители Пхукета и туристы.

Цель текущей работы — описать существующий продукт и определить желаемый MVP. Эти два состояния рассматриваются отдельно: наличие возможности в коде не означает, что она согласована как требование к MVP.

## Основание описания текущего состояния

Изучены текущие исходники и документация локального проекта, включая незакоммиченные изменения. Репозиторий GitHub — `EugeneSysoev/govolley`.

Сведения о запуске и проверках из истории проекта являются результатами прежних работ. В рамках подготовки этого описания приложение, тесты и production-окружение повторно не запускались.

## Техническое устройство

Проект организован как монорепозиторий Bun с Turborepo:

- frontend: Next.js;
- backend: NestJS;
- общие контракты: пакет `@govolley/shared-types`;
- хранение данных: PostgreSQL через Prisma.

Инженерный процесс уже настроен: инструкции для агентов, GitHub Issues, стандартные роли triage и один общий предметный контекст. Согласованные понятия хранятся в корневом `CONTEXT.md`.

## Текущее состояние продукта

По исходникам GoVolley — сайт школы с публичным расписанием, входом через Telegram, определением уровня игрока и самостоятельной записью и отменой записи.

| Сценарий | Реализация в текущем коде | Ограничения |
| --- | --- | --- |
| Расписание | Список активных тренировок, календарь и выбор даты, карточки занятий | Нет фильтров по уровню, локации и тренеру; серверный список включает прошлые активные занятия |
| Детали занятия | Дата, время, уровень, тренер, локация и заполненность; ссылка Google Maps для известной локации | Поля цены и описания существуют в данных, но на странице деталей не выводятся |
| Вход | Вход через Telegram-бота; пользователь создаётся автоматически | Других способов входа нет; доступность живого бота в этой работе не проверялась |
| Уровень игрока | Анкета из пяти вопросов, серверный расчёт одного из трёх уровней, направление нового пользователя в анкету | Повторное прохождение после установки уровня запрещено; ответы не сохраняются |
| Профиль | Имя, аватар, уровень и отметка его подтверждения, баланс, записи на занятия; изменение имени и аватара | Записи не разделены на будущие и прошедшие; отображение баланса не является платёжной системой |
| Запись | Авторизованный пользователь записывается при наличии места; повтор запроса не создаёт вторую запись | Нет проверки соответствия уровня, срока до начала или достаточности баланса; нет листа ожидания |
| Отмена записи | Ученик отменяет запись; повторная отмена не создаёт дополнительного действия | Нет срока отмены, штрафов, возвратов или уведомлений |
| Управление занятиями | Тренер и администратор создают, редактируют и скрывают занятия через интерфейс расписания | Обе роли управляют всеми занятиями; нет списка участников, посещаемости и повторяющегося расписания |
| Подтверждение уровня | API позволяет тренеру или администратору поставить либо снять отметку подтверждения | Нет полноценного интерфейса выбора ученика; существующая кнопка в профиле обращается к собственному пользователю |
| Оплата и абонементы | Есть отдельные поля баланса, цены и способа оплаты; главная показывает статические тарифы | Нет покупки, пополнения, списания, возврата, учёта абонементов или интеграции оплаты |
| Уведомления | Telegram-бот отвечает в сценарии входа | Нет подтверждений записи, напоминаний и сообщений об отмене или переносе занятия |

Наличие `paymentType: BALANCE` у создаваемой записи не сопровождается списанием или проверкой средств. Указанные на главной пакеты занятий являются контентом сайта, а не реализованной системой абонементов. Обещание погодных уведомлений в FAQ также не подтверждено соответствующим сценарием в коде.

Дата занятия в рассмотренных интерфейсах форматируется в часовом поясе браузера; единое применение времени Пхукета требует отдельного продуктового решения и проверки.

| Масштаб продукта | Одна школа |
| География | Пхукет |
| Основная аудитория | Русскоязычные жители Пхукета и туристы |
| Результат текущего этапа | Описание текущего состояния и желаемого MVP |
| Основной сценарий | Самостоятельная запись на тренировку |
| Форматы занятий | Только групповые тренировки |
| Оплата | На месте; онлайн-оплата не требуется |
| Абонементы | Пакеты на 5 и 10 групповых тренировок |
| Выдача абонемента | Тренер или администратор отмечает полученную оплату на месте и активирует абонемент |
| Остаток абонемента | Ученик видит количество оставшихся занятий в профиле |
| Своевременная отмена | Отмена минимум за 3 часа до начала сохраняет занятие |
| Срок действия абонемента | 90 дней от первой тренировки по абонементу |
| Списание занятия | При записи на тренировку с использованием абонемента |

| Отмена тренировки школой | Занятие возвращается |

| Уведомления в Telegram | Подтверждение записи, подтверждение отмены и отмена тренировки школой |

| Смена уровня | Существующие записи сохраняются; новый уровень ограничивает последующие записи |

### Согласованные правила абонементов

- В MVP предусмотрены два пакета: 5 групповых тренировок за 2200 ฿ и 10 групповых тренировок за 4000 ฿. Разовая тренировка стоит 500 ฿. Владелец подтвердил эти тарифы из текущего контента сайта.
- Ученик оплачивает абонемент на месте. Тренер или администратор фиксирует факт полученной оплаты и активирует пакет.
- В профиле ученика отображается остаток занятий по абонементу. Отображение денежного баланса в существующем коде не заменяет этот остаток.
- Срок действия пакета — 90 дней от первой тренировки по абонементу. Своевременная отмена первой записи или отмена школой не запускает срок. Посещение, поздняя отмена и неявка запускают срок от даты этой тренировки.
- Абонемент должен действовать на дату самой тренировки. Запись заранее не позволяет посещать занятия за пределами срока. Возврат восстанавливает остаток, но автоматически не продлевает срок и не делает истёкший пакет действующим.
- У ученика может быть несколько пакетов. Для записи используется подходящий пакет с ближайшей датой окончания. Ещё не начатые пакеты используются в порядке покупки. Остаток каждого пакета отображается отдельно.
- При записи с использованием абонемента остаток уменьшается на одно занятие. Повтор одной операции не должен приводить к повторному списанию.
- Если ученик отменяет запись минимум за 3 часа до начала, занятие сохраняется. Отмена ровно за 3 часа относится к своевременной.
- При своевременной отмене списанное занятие возвращается на абонемент. Повтор одной операции отмены не должен приводить к повторному возврату.
- Если отмена произошла менее чем за 3 часа до начала или ученик не пришёл, занятие расходуется.
- Если тренировку отменяет школа, занятие возвращается. Возврат в уже истёкший пакет сохраняет запись о возвращённом занятии, но не продлевает срок автоматически.
- Ученик может записаться на одну тренировку без абонемента и оплатить её на месте. Поздняя отмена или неявка по разовой записи фиксируется без автоматического долга и штрафа.

### Уровни и доступность групп

- Ученик может самостоятельно записаться только в группу своего уровня подготовки. Наличие свободного места остаётся обязательным условием.
- Тренер может изменить уровень ученика. Существующее действие подтверждения уровня не заменяет изменение самого уровня.
- Начальный уровень определяется обязательной анкетой после входа через Telegram и до первой записи. Предварительное подтверждение тренером для записи не требуется.
- Уже оформленные записи при смене уровня сохраняются. Новый уровень определяет доступность последующих самостоятельных записей.

### Работа тренера и администратора

В MVP сотрудник школы с ролью тренера или администратора должен иметь возможность:

- Просматривать список участников конкретной тренировки.
- Отмечать фактическое посещение.
- Отмечать полученную разовую оплату на месте.
- Фиксировать оплату и выдавать абонемент на 5 или 10 занятий.
- Просматривать остаток занятий по абонементу ученика.

Эти возможности согласованы для обеих ролей. Порядок назначения ролей, исправления отметок и учёта операций закреплён в разделе рабочих правил ниже.

### Вход и первый визит

Существующий Telegram-вход остаётся единственным способом авторизации в MVP. Новый ученик проходит обязательную анкету перед первой записью. Полученного уровня достаточно для самостоятельной записи в соответствующую группу; тренер может впоследствии его скорректировать.

Основной путь: просмотр расписания и занятия, вход через Telegram, анкета для нового ученика, самостоятельная запись. Запись может использовать абонемент или предусматривать разовую оплату на месте.

### Уведомления и отмена школой

- Telegram-бот отправляет подтверждение записи ученика.
- После отмены записи ученик получает подтверждение отмены.
- При отмене тренировки школой все записанные ученики получают сообщение; списанные занятия возвращаются.
- Перенос реализуется как отмена старой тренировки и создание новой. Автоматического переноса участников нет: ученик самостоятельно записывается на новую дату.
- Автоматические напоминания не входят в MVP и могут быть добавлены позднее.
- Ошибки доставки обрабатываются отдельно от записи и возврата; правила доставки и изменений заполненной тренировки закреплены ниже.

### Подтверждённая разница между текущим продуктом и MVP

Самостоятельная запись на групповые тренировки уже представлена в коде. Учёт абонементов является новым обязательным сценарием MVP: статические тарифы, поле баланса и значение способа оплаты у записи его не реализуют. Потребуются выдача оплаченных пакетов сотрудником, отображение остатка, списание при записи, возврат при своевременной отмене и отмене школой, а также ограничение срока действия пакета. Для разовой записи необходимо отдельно учитывать оплату на месте. Также потребуются список участников, отметки посещаемости, ограничение записи по уровню и изменение уровня тренером; текущая отметка подтверждения уровня не реализует весь этот сценарий.

Уведомления о записи и отмене также потребуют реализации: текущий бот обслуживает только вход.

## Критерии приёмки, выведенные из согласованных решений

Это согласованные целевые проверки будущей реализации, а не отчёт об уже пройденных тестах.

1. Новый ученик входит через Telegram, проходит анкету и может самостоятельно записаться в группу полученного уровня без предварительного подтверждения тренером.
2. Ученик другого уровня не может самостоятельно записаться в группу, даже если в ней есть места. После изменения уровня тренером доступ к новым записям соответствует новому уровню.
3. При разовой записи ученик видит цену 500 ฿ и условие оплаты на месте. Сотрудник видит запись в списке участников и может отметить полученную оплату.
4. Тренер или администратор может подтвердить оплату и выдать пакет на 5 занятий за 2200 ฿ либо на 10 за 4000 ฿. Ученик видит остаток в профиле.
5. Запись по абонементу уменьшает остаток ровно на одно занятие; повтор того же запроса не вызывает повторного списания.
6. Отмена за 3 часа или раньше возвращает занятие ровно один раз. Граница проверяется отдельно: 3 часа и 3 часа минус 1 секунда дают разные последствия.
7. При поздней отмене или неявке занятие по абонементу остаётся израсходованным.
8. Поздняя отмена или неявка по разовой записи фиксируется без автоматического денежного долга и штрафа.
9. Отмена тренировки школой возвращает списанное занятие каждому участнику по абонементу; повтор отмены не увеличивает остатки повторно.
10. Перенос не переносит учеников автоматически: новая тренировка требует новой записи ученика.
11. Тренер и администратор видят участников, отмечают посещение и оплату, выдают абонементы и просматривают остатки. Обычный ученик не получает этих полномочий.
12. Ученик получает Telegram-сообщения о записи, отмене своей записи и отмене тренировки школой.
13. Срок абонемента составляет 90 дней от первой тренировки. Своевременная отмена первой записи и отмена школой не запускают срок; посещение, поздняя отмена или неявка запускают его от даты тренировки.
14. Вместимость тренировки не превышается при конкурентных записях. Существующие гарантии одноразового входа, защиты ролей и согласованности записи сохраняются.
15. Запись на тренировку за пределами срока абонемента отклоняется, даже если попытка записи сделана до окончания срока. Возврат занятия не продлевает срок автоматически.
16. При нескольких пакетах списание происходит с подходящего пакета с ближайшим окончанием, а среди ещё не начатых — в порядке покупки. Повтор или конкурентные запросы не расходуют последнее доступное занятие дважды.
17. Изменение уровня не отменяет существующие записи. Попытка новой самостоятельной записи проверяется по актуальному уровню.
18. Часовой пояс устройства не меняет время школы: расписание и границы срока определяются по Пхукету. День первой учитываемой тренировки является днём 1; последняя допустимая тренировка приходится не позднее конца дня 90.
19. После начала тренировки новые самостоятельные записи не принимаются. Изменение даты, времени, площадки или уровня занятия с участниками требует отмены и создания нового занятия.
20. При наличии подходящего пакета он предложен по умолчанию; ученик может выбрать разовую оплату. Отсутствующий, пустой или истёкший пакет не создаёт списание в долг.
21. Только администратор назначает или снимает роль тренера. Исправление отметки оплаты или посещения сохраняет автора, время и основание и не повторяет списание.
22. Сбой Telegram не откатывает успешную операцию. Повтор доставки не повторяет списание или возврат; недоставленные сообщения доступны сотруднику для контроля.

## Согласованные рабочие правила

Правила и способ проверки ниже подтверждены владельцем при итоговой сверке 19 октября 2026 года.

### 1. Время, срок и расписание

- Все даты и время школы отображаются по Пхукету (`Asia/Bangkok`) с явной подписью, независимо от часового пояса устройства.
- Первая учитываемая тренировка задаёт день 1. Абонемент действует по конец дня 90 включительно по времени Пхукета.
- Самостоятельная запись доступна до начала тренировки; после начала новые записи не принимаются. При заполненной группе запись недоступна, листа ожидания в MVP нет.
- Для публикуемой тренировки обязательны название, дата, время начала и окончания, уровень, вместимость, площадка, тренер и цена. Разовая цена — согласованные 500 ฿. Описание необязательно.
- При изменении времени, даты, площадки или уровня тренировки с участниками применяется согласованный сценарий отмены и создания новой. Редактирование описания и имени тренера не переносит занятие. Уменьшение вместимости ниже числа записанных запрещено.

### 2. Выбор способа оплаты

Если есть подходящий абонемент, он выбран по умолчанию с показом пакета и остатка после записи. Ученик может явно выбрать разовую оплату на месте вместо абонемента. При отсутствии подходящего пакета доступна только разовая оплата; списаний в долг нет.

### 3. Полномочия и исправления

- Тренер и администратор работают со всеми тренировками школы, а не только с собственными.
- Администратор назначает и снимает роль тренера; обычный пользователь не может изменить себе роль. Первоначальная административная учётная запись назначается владельцем через управляемую настройку окружения.
- Тренер и администратор могут исправлять ошибочные отметки посещения и разовой оплаты. Исправление не запускает повторное списание или возврат занятия.
- Выдача, списание, возврат и исправление сохраняют автора, время и основание. Остаток вычисляется из учтённых операций; произвольного редактирования числа в профиле нет.

### 4. Сбой Telegram

Ошибка доставки сообщения не отменяет успешную запись, возврат или отмену тренировки. Операция остаётся видимой на сайте; доставка повторяется, а недоставленные сообщения доступны сотруднику для контроля. Повтор доставки не повторяет списание или возврат.

### 5. Границы первой версии

Подтверждённые границы: одна школа, групповые тренировки, русский язык, Telegram-вход, оплата на месте, два вида абонементов. Онлайн-оплата, индивидуальные тренировки, свободные игры, турниры и автоматические напоминания в согласованный MVP не входят.

За пределами MVP остаются лист ожидания, заморозка и передача абонемента другому человеку, денежные возвраты, автоматические штрафы, промокоды, повторяющееся расписание и отдельная система управления несколькими школами. Информационные страницы и существующий визуальный стиль сохраняются; редизайн не является задачей этого этапа.

## Согласованный способ проверки реализации

Основная граница проверки — внешний HTTP API приложения с настоящей отдельной тестовой PostgreSQL. Проверяются наблюдаемые результаты: список участников, остатки пакетов, история операций, доступность записи и права пользователя. Подменять PostgreSQL при проверке конкурентных списаний и бронирований нельзя.

В проекте уже есть подходящая основа: `apps/backend/test/core.postgres-spec.ts` проверяет конкурентную запись на последнее место, повторные операции, роли и одноразовый вход через HTTP и реальную БД. Новые сценарии абонементов, срока, отмен и исправлений следует проверять через эту же границу. Время в проверках управляется явно, чтобы воспроизводить границы 3 часов и 90 дней.

Браузерные проверки дополняют интеграционные: первый вход и анкета, запись с абонементом, разовая запись, остатки в профиле, отмена и рабочий экран сотрудника. Используется существующий подход `scripts/browser-smoke.mjs` с настоящими frontend/backend/тестовой БД; внешнее подтверждение Telegram заменяется fixture. Доставку уведомлений проверяет контролируемый адаптер Telegram, включая сбои и повторы; доступность живого бота проверяется отдельно при подготовке запуска.

Проверки ориентированы на поведение пользователя и результаты операций, а не на вызовы внутренних методов. При реализации также выполняются относящиеся к изменениям проверки типов, lint, сборка и существующие регрессионные сценарии. Сейчас перечислен план проверок; тесты в этой работе не запускались.
