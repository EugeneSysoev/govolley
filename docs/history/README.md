## 2026-10-19 — описание продукта и согласованный MVP

- После интервью с владельцем зафиксированы [описание текущего состояния и целевого MVP](../PROJECT.md), [спецификация для реализации](../MVP-SPEC.md) и [доменный глоссарий](../../CONTEXT.md). Требования, границы и способ проверки подтверждены владельцем.
- Спецификация опубликована как [GoVolley MVP](https://github.com/EugeneSysoev/govolley/issues/1) с созданной меткой `ready-for-agent`: 50 пользовательских историй и 25 сценариев приёмки. Текст задачи и локальной спецификации совпадает полностью.
- Согласованы одна школа на Пхукете, групповые тренировки, Telegram-вход с анкетой, запись по уровню, разовая оплата 500 ฿, абонементы на 5/10 занятий за 2200/4000 ฿, срок 90 дней от первой учитываемой тренировки и своевременная отмена минимум за 3 часа.
- Определены рабочие сценарии тренера и администратора, история учётных операций, три вида Telegram-уведомлений, перенос через отмену и создание новой тренировки и правила нескольких абонементов.
- Основная граница будущей проверки — HTTP API с настоящей отдельной тестовой PostgreSQL; браузерные сценарии и контролируемый адаптер Telegram дополняют интеграционные проверки.
- Документы подготовлены чтением текущего рабочего дерева, включая незакоммиченные исходники. Код приложения, БД и окружения не менялись. Тесты, сборка и повторный аудит не запускались; STD-xxx/SPEC-xxx не закрывались. Целевая функциональность не объявляется реализованной.

## Как читать историю

Перед изменениями сверяйте исторический результат с текущим кодом и открытыми замечаниями. Исправления 2026-10-18 и дополнительные находки 2026-10-19 имеют разный охват: сохранённый статус F1–F14 не закрывает автоматически новые SPEC-xxx и STD-xxx.

Исторические отчёты сохраняйте как снимки результата на указанную дату. Актуальные статусы новых замечаний ведите в файле ревью и согласованном трекере; при последующих исправлениях добавляйте отдельную запись с результатами проверок.
