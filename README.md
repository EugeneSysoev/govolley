# GoVolley

GoVolley — сайт одной школы пляжного волейбола на Пхукете для русскоязычных жителей и туристов.

Монорепозиторий Bun 1.4.2: NestJS 11, Next.js 16, Prisma 7 и PostgreSQL.
Нужен работающий Node.js 22.12+ (проверено на 24.19.0). Секреты в Git не хранятся.

## Запуск

1. `bun install --frozen-lockfile`.
2. Скопировать `apps/backend/.env.example` в `apps/backend/.env`, а frontend-пример — в `apps/frontend/.env.local`; заполнить значения локально.
3. `bun run --cwd apps/backend prisma:generate`.
4. Для своей development-БД применить `bun x prisma migrate deploy` из `apps/backend`.
5. `bun run dev` — backend на 3000, frontend на 3001. Общий пакет предварительно собирается через граф Turbo.

`BACKEND_URL` — серверный HTTP origin **без `/api`**, обязателен в production, например `https://backend.example.com`.
Он используется SSR, NextAuth и fallback rewrites. При его изменении нужна пересборка frontend.
Браузер обращается только к относительному `/api`; Next.js сначала обрабатывает собственные маршруты, включая `/api/auth/[...nextauth]`.
Аватары доступны через `/uploads`. `NEXT_PUBLIC_API_URL` и `NEXT_PUBLIC_BACKEND_URL` больше не используются.
`NEXTAUTH_SECRET` должен совпадать на backend и frontend, оставаться серверным и иметь достаточную случайность.
`NEXTAUTH_URL` — внешний origin frontend. В браузер попадает только публичный MapTiler key; ограничивайте его доменами у провайдера.
Работа Telegram-бота требует `TELEGRAM_BOT_TOKEN`; тесты не обращаются к Telegram.

## Проверки

```sh
bun run build
bun run typecheck
bun run lint
bun run test
bun run test:e2e
bun audit --json
```

Backend unit tests и HTTP smoke не требуют БД. Frontend tests проверяют реальные компоненты с подменой HTTP/сессий там, где это необходимо.
Lint не изменяет исходники автоматически. Предупреждения о существующих `<img>` не отключены.
Общий пакет `@govolley/shared-types` компилируется в `dist`; при изменении его исходников во время разработки пересоберите пакет и перезапустите потребителей.

### Отдельная тестовая PostgreSQL

```sh
docker compose -f compose.test.yml up -d --wait
export TEST_DATABASE_URL='postgresql://govolley_test:test-only@127.0.0.1:55439/govolley_test'
export NODE_OPTIONS='--experimental-vm-modules'
bun run test:db:prepare
bun run test:integration
```

PowerShell: вместо `export` используйте `$env:TEST_DATABASE_URL='...'` и `$env:NODE_OPTIONS='--experimental-vm-modules'`.
VM modules нужны для встроенного NestJS валидатора сигнатур файлов в Jest; проверка MIME не подменяется.
`test:db:prepare` и integration tests принимают только loopback-адрес и имя БД с окончанием `_test`.
Они не читают production `.env`. Тесты создают собственные записи и удаляют только свои fixtures; все старые миграции неизменны.
Compose поднимает временную БД в tmpfs с тестовым паролем, опубликованную только на localhost.
После проверки: `docker compose -f compose.test.yml down`.

### Браузерный smoke

Использует настоящий Chrome, production Next.js, NestJS и отдельную PostgreSQL; только подтверждение Telegram заменено fixture.
Нужны свободные порты 55440/55441 и Chrome (либо `TEST_BROWSER_CHANNEL=msedge`).

```sh
export BACKEND_URL='http://127.0.0.1:55440'
bun run build
bun run test:browser
```

`TEST_DATABASE_URL` должен указывать на подготовленную тестовую БД. Harness запускает и завершает свои HTTP-серверы и очищает fixtures.
Он проверяет реальный NextAuth catch-all, одноразовый вход, видимость онбординга после главной/перезагрузки, серверный расчёт уровня,
защиту session update, SSR с пустой локацией, отмену заполненной группы и подтверждение уровня после выхода/повторного входа.
Живой Telegram и карта с внешними тайлами проверяются отдельно.

## Авторизация и доступ

`AuthSessionService` — единственный источник политики ссылки входа: TTL **10 минут** от создания для PENDING и CONFIRMED.
Статус не возвращает пользователя. Подтверждение Telegram атомарно привязывает первую личность; повторное подтверждение запрещено.
Обмен атомарно переводит CONFIRMED в CONSUMED и выдаёт JWT на прежние 30 дней. Ровно один конкурентный обмен успешен.
При ошибке подписания транзакция откатывается. При потере HTTP-ответа или сбое создания cookie после успешного обмена нужно начать новый вход:
повторная выдача по sessionId намеренно запрещена. CONSUMED — временная запись, а не постоянный credential.
Очистка раз в 10 минут удаляет все сессии старше TTL; безопасность не зависит от своевременного запуска очистки.
Polling завершается при expired/consumed/ошибке и очищает таймер/запросы при отмене или уходе.

Каждая защищённая операция проверяет JWT и актуального пользователя/роль в БД.
Создание, редактирование и мягкое удаление тренировок разрешены COACH и ADMIN. Владение тренировками в текущей модели отсутствует.

Первого администратора владелец назначает отдельной командой `bun run admin:bootstrap` по проверенному Telegram ID существующего аккаунта. Инструкция и проверка: [настройка администратора](docs/admin-setup.md). Назначение и снятие роли тренера доступны администратору в профиле по ссылке «Управление тренерами».
Анонимный запрос получает 401, обычный USER — 403. Подтверждение уровня доступно тем же ролям.
Профиль не принимает role, isLevelVerified, skillLevel, image-путь и другие служебные поля.
NextAuth игнорирует поля клиентского `update()` и перечитывает профиль с backend; профиль также обновляется при открытии/возврате фокуса.

## Бронирование и контракты

Запись, отмена, изменение вместимости и мягкое удаление берут одну PostgreSQL row lock на тренировку.
Проверка активности, существующей брони и числа CONFIRMED выполняется под блокировкой в той же транзакции, что и изменение.
Повтор записи/отмены идемпотентен. После CANCELLED можно записаться снова, если есть место и тренировка активна.
Недостаток мест, неактивная тренировка и уменьшение лимита ниже существующих броней дают 409.
Мягкое удаление сохраняет существующие брони: детали и отмена доступны, новая запись запрещена.
Вместимость гарантируется для записей через эти сервисы; ручные SQL-изменения должны соблюдать тот же протокол.

Общий контракт Training отделён от create/update. `isBooked` относится к текущему пользователю, `currentParticipants` считает только CONFIRMED.
`location`, `description`, `price`, `coachName` допускают null. Пустая локация отображается как «Уточняется».
Zod проверяет HTTP payload до сервиса: служебные поля, даты ISO, HH:mm, целые лимиты 1–100, неотрицательную цену.
Для частичного изменения времени сервис дополнительно проверяет объединённое состояние. Тренировка заканчивается в тот же день позже начала.

Анкета принимает ровно пять целых ответов 1–4; сумма вычисляется сервером.
Утверждённые пороги: 5–14 BEGINNER, 15–17 INTERMEDIATE, 18–20 ADVANCED.
Повторное прохождение после установленного/подтверждённого уровня возвращает 409.

## Аватары и развёртывание

Новая миграция `20261018000000_avatar_key` добавляет nullable `User.avatarKey` без преобразования старых недоверенных путей.
Перед выкладкой кода примените её штатным `prisma migrate deploy` в целевом окружении по принятой процедуре резервирования.
В этой работе миграции применялись только к отдельной тестовой БД.
Существующие безопасные legacy-аватары остаются видимыми, но старые `image` никогда не используются для удаления.
Новые файлы имеют UUID-ключ и определяемое сервером расширение; внутренний ключ не возвращается в профиль.
Разрешены PNG/JPEG/WebP по сигнатуре содержимого, один файл до 5 MiB и ограниченное число multipart-полей.
Файл сначала сохраняется, БД обновляется под блокировкой пользователя, прежний файл удаляется после commit.
При ошибке БД новый файл удаляется только после проверки отсутствия ссылок; при неоднозначном commit/недоступности БД очистка откладывается ради сохранения актуального аватара.
Не удаляйте legacy/отложенные файлы по клиентским строкам: ручная очистка требует сверки с БД и разрешённым каталогом.

Из логов удалены DATABASE_URL, JWT/accessToken и содержащие их объекты. Старые журналы стоит проверить на утечку credentials БД и действующих bearer-токенов;
потенциальная ротация выполняется отдельно владельцем окружения. Production-секреты этой работой не менялись.

## Оставшийся аудит

Next.js 16.4.2, Multer 2.4.0 и NestJS 11.2.7 закрывают D1/D2 и проверены сборкой/multipart HTTP.
NextAuth обновлён до 4.24.15; Prisma — до совместимой 7.10.1. Остальные обновления ограничены отмеченными аудитом пакетами и совместимыми диапазонами.
Сканер продолжает отмечать MapLibre внутри MapTiler SDK: SDK пока закрепляет несовместимую с исправленной major-веткой зависимость.
В приложении отключено создание attribution control, принимающего сторонний HTML; вместо него используются статические React-ссылки на правообладателей.
Это ограничение атакуемого пути, а не исправление самой библиотеки. Обновление SDK на совместимую исправленную версию остаётся задачей сопровождения.
`braces` и `sprintf-js` остаются транзитивными инструментами lint/build/coverage; недоверенные сетевые шаблоны/format strings в них проект не передаёт.
Аудит не считается чистым. Детали, источники и результаты проверок — в [отчёте об исправлениях от 2026-10-18](docs/history/2026-10-18/GOVOLLEY_FIXES.md). Последующие работы перечислены в [истории проекта](docs/history/README.md); новые открытые замечания — в [результатах ревью](docs/agents/code-review-findings.md).
